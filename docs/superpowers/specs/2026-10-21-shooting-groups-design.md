# 拍摄组工作台升级

用户确认 UI 方案并授权实施；新分支 `feature/shooting-groups` 从 `fix/heavy-camera-950g` 创建。左侧主要按钮最终名称为「启动机械臂」「关闭机械臂」，关闭沿用 Home 零位后失能。动作块沿用现有 J1–J6 拖动轨迹录制，不改为单姿态点。额定相机固定 950 g，质量分布/质心和有效增益尚未完成辨识，本次不增加随意输入重量即自动适配的功能。

## 数据和界面

- 默认三个拍摄组，每组四个动作块，可新增/删除/重命名组与块，组间隔默认五秒，可设 0–60 秒。
- 元数据保存在 `logs/runs/shooting_groups.json`，轨迹采样继续使用 `teach_trajectories.json`。首次迁移把所有旧轨迹链接到第一组，不改写旧样本；空块首次录制才分配槽位。已有组文件不重复导入，坏文件拒绝覆盖。
- 每组最多 20 块、最多 20 组。删除仅移除分组链接，原轨迹保留在原采样文件，部署另有备份。元数据和新采样使用原子写入。
- 单独播放/整组播放要求已手动启动。按用户后续反馈，整组播放改为执行全部已保存动作，空块在界面与确认框明确列出并跳过；全部为空或任何选中的已保存动作不合法时不开始。全部动作完成后保持使能，用户点击关闭进行收尾。
- 组播放停止按钮和独立紧急停止停止动作并保持使能；额外紧急失能入口保留明确提示。网页刷新只读取状态，不启动、重发动作或触发快门。

## 执行与并发

- 一个后端工作线程拥有整组流程，不由浏览器定时调用多个动作。开始前冻结组顺序与样本快照，并检查所有动作的样本数量、有限数值、递增时间及软件角度范围。
- 段间以有限速度的平滑过渡连接当前角度和下一段起点，执行完每段后等待配置间隔；最后一段后不等待。等待可被停止/关闭/紧急失能中断。
- 任何段异常均终止整组，不继续下一段。编辑、重录和删除在动作执行/录制/Home 时拒绝；HTTP 控制命令串行处理，紧急失能有即时取消信号。
- Home 和工作线程切换先确认旧线程结束，避免两个线程下发命令。Home 循环也检查取消，紧急失能后不得继续发送或重新使能。
- 沿用当前控制增益、补偿、限幅和软件边界（J2 +100°、J4 +80°、J6 -70°），本次不宣称这些范围经过物理安全校准。
